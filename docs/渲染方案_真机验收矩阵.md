# 渲染方案系统 · 真机验收矩阵（PR #8）

> **本文件是合并前门槛，不是已完成记录。**
>
> 当前实现**只**在 Fake `bpy` 上验证过结构正确性、幂等性与可恢复性
> （见 `tests/test_render_schemes.py`）。**没有任何一条在本文件里勾选为「通过」** ——
> 只有在一台装有 Blender 的机器上按下面步骤实际跑过，才能勾选。
>
> 交付方不得以「自动测试全绿」代替真机验收：自动测试证明不了渲染效果，
> 也证明不了两条灯光方案在真实 EEVEE 下确实产生了预期画面。

## 0. 环境前提

| 项 | 要求 |
| --- | --- |
| Blender | 与本项目其余渲染流程使用同一大版本（建议 4.x） |
| EEVEE | 体积雾方案必须用 EEVEE（Cycles 的体积表现不同，不在本矩阵范围内） |
| 测试模型 | 至少两个：一个纯 `.pmx`、一个 `.blend` |
| 测试工程 | 含原灯光的工程一份（用于验证「原灯只停用不删除」与结束恢复） |

## 1. 逐项验收

每条都要记录**实际观察到的现象**与**产物路径**，不能只写「通过」。

### 1.1 经典方案（classic）

- [ ] **A1** 选 `classic`，渲染 `.pmx`：终态为 `success` 且 `shippable=true`。
- [ ] **A2** 灯名与数量与重构前**完全一致**（对照 `一键卡通渲染.py` 的
  `LIGHTS_ACTIVE` / `LIGHTS_SPARE`；可用 Blender 大纲面板逐个数）。
- [ ] **A3** 画面与重构前的 `legacy` 渲染结果**肉眼一致**（同模型、同模式）。
- [ ] **A4** 渲染结束后：`run_manifest.json` 的 `render_scheme.id == "classic"`；
  `scene_restore.restored == true`。
- [ ] **A5** 渲染结束后场景里**没有** `TOON_体积雾灯光组` / `TOON_灯光总控`。

### 1.2 体积雾方案（volume_fog）

- [ ] **B1** 选 `volume_fog`，渲染 `.pmx`：终态 `success`、`shippable=true`。
- [ ] **B2** 出现 `TOON_体积雾灯光组`（7 盏 `LGT_*` + `TOON_灯光总控`）与
  `VOLUME_01_程序化体积雾`。
- [ ] **B3** 原工程里的灯**仍在**（大纲面板里能看到），但 `hide_render` 已勾选。
- [ ] **B4** 黑色无环境光世界生效（背景为纯黑，无环境光染色）。
- [ ] **B5** 改 `fog_density`（例如 0.005 / 0.05 / 0.1 三档）分别渲染：
  雾的浓度肉眼可见地变化，且**始终在允许范围内**。
- [ ] **B6** 同一模型连续渲染两次：第二次不出现灯组/雾对象**翻倍**。
- [ ] **B7** `run_manifest.json` 的 `render_scheme.id == "volume_fog"`，
  `parameters.fog_density` 等于提交值。

### 1.3 场景恢复

- [ ] **C1** 渲染结束（成功）后：世界回到原世界、原灯 `hide_render` 恢复为原值、
  活动相机与合成器 `use_nodes` 恢复、渲染体积设置恢复。
- [ ] **C2** 渲染**失败**（人为制造，如临时改坏输出路径）后同样恢复。
- [ ] **C3** 渲染**中途取消**后同样恢复。
- [ ] **C4** 若恢复未通过回读确认：日志里必须出现
  `RENDER_SCHEME_RESTORE_FAILED`，且**不得**谎报成功。

### 1.4 `.blend` 模型

- [ ] **D1** `classic` + `.blend`：走 `--blend` 路径，终态 `success`。
- [ ] **D2** `volume_fog` + `.blend`：同上。

### 1.5 旧接口兼容（弃用别名）

- [ ] **E1** 用旧参数 `--lighting legacy` 仍能跑通，且日志出现弃用提示，
  实际生效方案为 `classic`。
- [ ] **E2** 用旧参数 `--lighting volume_fog --fog-density 0.03` 仍能跑通，
  实际雾密度为 0.03。
- [ ] **E3** 同时给 `--scheme classic --lighting volume_fog` 时**被拒绝**
  （报 `RENDER_SCHEME_INVALID`），不静默取其一。

### 1.6 Web 端

- [ ] **F1** 页面能读到方案清单，默认方案 = 服务端返回的 `default`。
- [ ] **F2** 切换方案保留各自草稿；切到经典方案时不带体积雾参数。
- [ ] **F3** 雾密度填超范围值时：就地报错且**阻止提交**（不发请求）。
- [ ] **F4** 任务详情正确显示方案 / 版本 / 生效参数 / 画面模式 / 辉光配置 /
  场景恢复状态 / 是否可交付。
- [ ] **F5** `GET /api/render/schemes` 响应中**不含**任何本机路径。

## 3. 明确的未验证项（不得声称通过）

- 两条方案在真实 EEVEE 下的**画面观感**（冷暖分离、体积雾厚薄）未经确认。
- `light_intensity` / `cool_rim_intensity` / `warm_rim_intensity` / `black_world`
  四个参数**尚未标定**，因此刻意保持只读；标定完成前不得开放为可调项。
- 大模型 / 高面数场景下的性能影响未经测量。
