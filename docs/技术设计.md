## 2. 已探明的 Blender MCP 协议（实测）

插件本体：`%APPDATA%\Blender Foundation\Blender\5.2\scripts\addons\blender_mcp.py`
进程实测：`127.0.0.1:9876` LISTENING。

**传输层**：TCP socket。客户端发送**一个完整的 JSON 对象**（如 `{"type": "ping", "params": {}}`）；服务端把命令排入队列，由 Blender 主线程的 timer 取出执行，再把响应 `json.dumps` 后 `sendall` 回客户端。

**注意（与需求文档的差异）**：响应**没有换行分隔符**，不是严格的行分隔 JSON。收发两侧都是「累积缓冲 → 尝试 `json.loads` → 成功即视为一条完整消息」。因此客户端必须做增量 JSON 解析，不能按 `\n` 切分。

**响应格式**：`{"status": "success" | "error", "result": {...}}`。

**可用命令（只读相关）**：

- `ping` → `{"status":"success","result":{"pong":true}}`（无 bpy 访问，用于纯粹连通性探测）
- `get_scene_info` —— 场景、相机、渲染引擎等
- `get_world_state_snapshot`
- `get_addon_info`
- `get_object_info`
- `list_scene_items`
- `get_viewport_screenshot`
- **`execute_code`** —— 在 Blender 主线程执行任意 Python，返回结果 ★ 桥接层的关键入口

**桥接层结论**：MCP 原生没有协议版本、任务 ID、能力查询、错误码、状态查询等高级语义。这些将由本地控制服务在 MCP 之上**自建会话协议层**实现：

1. 所有写操作/渲染都通过 `execute_code` 下发，并在 Python 侧包一层返回 `{job_id, ok, effective_values, warnings, elapsed, image_path}`。
2. 由于 MCP 不主动推送，控制服务对长任务采用**短间隔非阻塞轮询**（`job_id` 查询脚本注入的进度变量），不使用固定 sleep。
3. 若后续发现 `execute_code` 无法满足（例如需要跨命令保持 Python 进程内状态），则在 Blender 端以一个**常驻 Python 模块**（经 `execute_code` 首次加载后驻留 `bpy` 模块命名空间）承载会话状态。

## 3. 三层架构

```
浏览器 Web UI  ⇄(HTTP+WS)⇄  本地控制服务(Node)  ⇄(TCP JSON)⇄  Blender MCP :9876  ⇄  Blender 主线程
```

- **本地控制服务**：校验参数 schema/类型/范围与模式适用性；任务排队、取消、去抖；保存预设/缩略图/运行记录；向前端推送状态。默认仅监听 localhost，启动时生成随机令牌校验请求。
- **Blender 桥接**：读当前场景与角色、建/查卡通管线、采集真实参数、从基线恢复、应用参数集、执行预览/正式渲染、回传实际生效参数与警告。

## 5. MVP 最小闭环（首个里程碑）

```
连接 9876 → 读取当前场景 → 建立基线 → 调整曝光/辉光(L0)
  → 自动预览（去抖 250–400ms）→ 恢复基线 → 保存预设
```

拆分任务：

1. **M1 连通性**：控制服务连上 9876，`ping` + `get_scene_info` 并在前端状态栏显示。
2. **M2 会话协议层**：`execute_code` 封装、`job_id` 分配、状态查询、错误码。
3. **M3 基线**：读取受控属性/节点插座/灯光/修改器 → 内存快照；初始化成功即出基线预览。
4. **M4 L0 参数**：曝光、Gamma、辉光五参数等；前端草稿 → 去抖 → 完整草稿应用 → 预览。
5. **M5 无污染校验**：连续预览后受控灯光/节点/修改器数量不增加；恢复基线后关键状态与快照一致。
6. **M6 预设**：保存/加载 JSON 预设（含 configured / effective / active 三套值）。

验收见需求文档 §17。

## 6. 预览取景（构图）实现设计

对应需求文档 §20。模块：`src/server/framing.py`。

### 6.1 构图唯一真源：`camera.data.view_frame()`

不自己推导 lens / sensor_fit / shift_x / shift_y / 渲染纵横比的组合效果，一律以 Blender 的
`camera.data.view_frame(scene=scene, apply_shift=True)` 返回的四个角点为唯一真源。

**关键陷阱（实测踩过）**：`view_frame()` 返回的三个向量**不在单位距离上** —— 与 `sensor_fit` 平行的方向上，半高恒为 `0.5`，
深度方向实测 `z ≈ -2.854`，并不是 `z = -1`。若直接拿 `x/y` 当「单位距离处的半宽/半高」用，`shift` 会被放大数倍，
算出「无论多远都装不进画面」的错误结果（首版得到 `distance = 16777216`、`worst = 1.4666`）。

正确做法：先用 `depth = -max(zs)` 把四个点归一化到单位距离，再取 `half_w / half_h / cx / cy`（`cx/cy` 即 shift 在画面上的等效偏移）。

修正后实测（`Duo_Vertical_MMD_Camera`，lens 68.4966 / VERTICAL / shift (0.4, -0.16)）：
`half_w = 0.0956`、`half_h = 0.1752`、`cx = 0.1402`、`cy = -0.0561`。这也解释了为什么 shift 必须站在 fit 方向的传感器尺寸口径上理解。

### 6.2 入画判定

世界点 `P` 在相机空间 `q = R^T (P - C)`；`u = q.x / q.z + cx`、`v = q.y / q.z + cy`（注意 Blender 相机朝 `-Z`，故用 `-q.z` 作深度）。
完整入画当且仅当 `|u| <= half_w` 且 `|v| <= half_h`。

越界比例按需求口径报「超出画面边长的比例」：`overflow = max(0, -min_u - 1)` 之类，而不是简单取 `min`，这样「自动取景后全 0」才成立。

### 6.3 自动取景解析解

不迭代试探，直接解：对包围盒每个角点 `(a, b, c) = R^T @ (corner - aim)`，要求 `|a| / (d - c) <= hw` 且 `|b| / (d - c) <= hh`，
取 `d = max_corner( c + max(|a| / hw, |b| / hh) )` 即最小可行距离。安全边距通过把 `hw / hh` 除以 `(1 + margin)` 实现：
15% 边距即 `hw / 1.15`，实测 `worst_ndc = 0.869565 = 1 / 1.15`，与理论值精确吻合。

临时相机朝向沿用原相机的旋转（因此仍保持工程的美术视角），shift 归零，只解算距离。

### 6.4 角色筛选

按骨架分组，取面数最多的一组为主要角色。排除规则：`rigid_body` 代理、命名模式匹配（`outline` / `shell` / `描边` / `轮廓` / `rigid` / `物理` / `刚体` / `インジケータ` / `ガイド` / `ダミー` / `操作`）、
`hide_render`、不可见、无材质槽。本工程实测：139 个网格里 138 个是带「物理」材质的刚体代理，唯一角色是 `model_mesh`（35544 面）。

### 6.5 临时相机生命周期

`bpy.data.cameras.new` + `bpy.data.objects.new` + `scene.collection.objects.link` 创建；
渲染体包在 `try/finally` 里，`finally` 中先恢复 `scene.camera = 原相机`，再 `bpy.data.objects.remove` / `bpy.data.cameras.remove`。
三个清理动作各自独立 `try/except`，保证任一环节抛错都不会阻断后续恢复 —— 渲染失败也一定能还原。

### 6.6 基线失效闸门

`framing.build_context_code()` 是**只读探针**，返回 frame / camera / transform / lens / shift / 角色包围盒 / 投影结果。
`session.submit()` 在建任务**之前**调用 `_assert_framing_fresh()`：先跑一次只读探针，与基线快照比对，
硬失效（帧变、相机变、位移、旋转、焦距、shift）直接抛 `FRAMING_STALE`（409，retryable），软告警只附在结果里。

渲染脚本另带 `_expect_frame` / `_expect_camera` 双重校验，即使闸门与渲染之间发生竞态，渲染体内也会主动中止，不会产出误导性画面。

### 6.7 白名单与无注入

取景代码与参数代码一样是**白名单驱动生成**：`framing.validate_options()` 只接受 `mode`（4 个 Literal 之一）与 `margin`（`0 <= m <= 0.4`），
未知字段一律 `PARAM_INVALID`；`REGION_RULES` 等字面量经 `repr` 量化后注入，客户端无法夹带任意 Python。

### 6.8 预览分辨率

按工程分辨率等比缩放到**长边 990**，保持纵横比（`binder.preview_resolution_for`）。取景诊断与实际渲染必须共用同一画面形状，
否则「入画」判定与实际画面不一致。本工程 1080×1980 → 540×990，与旧固定值巧合一致。

## 7. 依赖枚举（视图变换 → Look）实现设计

对应需求文档 §21。模块：`src/server/color_looks.py`，配合 `blender_ops.py` / `session.py` / `app.js`。

### 7.1 为什么 RNA 枚举与 OCIO 全局名单都不能采信

- `scene.view_settings.bl_rna.properties['look'].enum_items` —— 后台上下文里只返回 `NONE`（Blender 5.2.1 实测 `items_count == 1`），**完全不可用**；
- `PyOpenColorIO.getLookNames()` —— OCIO 配置的**全局** look 名单，是各视图合法集合的**超集**，不是当前 `view_transform` 下 Blender 接受的枚举。旧实现拿它当候选，于是把 AgX 专属档位写进了只接受通用档位的视图。

两者只能当**探测原料**，合法性必须问 Blender 本人。

### 7.2 权威允许列表来自 Blender 自己的报错文本

写一个必然非法的哨兵值触发枚举校验失败，报错格式实测稳定：

```
bpy_struct: item.attr = val: enum "X" not found in ('None', 'High Contrast', ...)
```

取 `not found in (` 到最后一个 `)` 之间的内容，先 `ast.literal_eval("(" + body + ")")` 严格解析，失败再退化为逗号切分。比逐项赋值探测既快又准：9 个视图一次扫描即拿到全部权威集合（`source == "rna"`），失败才退化为赋值探测（`source == "probe"`）。

解析逻辑**只有一份实现**：`color_looks._PARSE_ENUM_ERROR_TEXT_SRC`（源码字符串常量）。宿主侧用 `exec` 取出可调用对象（`_parse_enum_error_text`），Blender 侧把同一段源码内嵌进下发代码（`_parse_enum_error` 是它的薄封装），从根上杜绝两份实现漂移。

### 7.3 只读探针的恢复语义

`build_sweep_code()`（全量）与 `build_probe_code(vt, identifier)`（单视图）都在 `finally` 中恢复原 `view_transform` / `look`，并在载荷里回报 `original` / `restored.ok`。
`binder.read_look_capability()` 在 `restored.ok` 为假时**直接抛** `BLENDER_SCRIPT_ERROR`，绝不把「扫描后状态被改坏」当成成功。

注意：`build_probe_code` 的 `identifier` 省略时必须传 Python `None`，不能退化成字符串 `"None"` —— 后者恰好是一个合法的 look identifier，会把探测结果带偏。

### 7.4 value / label 分离

- `value`：Blender 真实 identifier，**唯一**允许写入 Blender 的东西；
- `label`：显示文本，由 `look_label()` 组合 —— `AgX` / `False Color` 这类「族前缀」视图下为 `"<视图> - <档位>"`，其余与 identifier 相同。

`normalize_options()` 输出 `[{value, label}]`；`params.ParamSpec.to_public()` 走同一套 `_as_option()`，旧的纯字符串项自动 `label = value`，因此 `params.py` 的静态回退与运行时能力表结构一致。

### 7.5 归一化优先级（`resolve_look`）

按顺序尝试，命中即返回：

1. 命中 allowed 的**真实 identifier**；
2. 命中 allowed 项的**显示标签**（老版本里带前缀的那串才是 label）；
3. 通用短名命中**族前缀 identifier**（后缀匹配）—— 让「AgX + `High Contrast`」成立；
4. `" - "` 前缀形式的**后缀**命中 allowed（`"AgX - High Contrast"` → `"High Contrast"`）。

以上均忽略大小写；全部落空才判非法（`ok=False` 并回传 `allowed`）。

### 7.6 写入顺序与原子化

`blender_ops.build_set_code()` 按固定阶段生成：`view_transform` → `look` → `exposure` → `gamma` → 其他。

生成的脚本先 `_snapshot()` 记录这四值，任一阶段失败即 `_restore()` 回滚，并输出结构化 `applied` / `failure` / `restored_to` / `restore_ok`。`None` 值的参数**跳过**，绝不当成字符串 `"None"` 写入。
`look` 阶段在赋值前调用 Blender 侧 `_allowed_looks()` 复核一次；非法则抛内部 `_InvalidLook`，由 `failure_to_error()` 翻译成 `INVALID_DEPENDENT_ENUM`。

### 7.7 执行前依赖校验

`session._assert_dependent_enums()` 在**调用 Blender 之前**对 `color.look` 调 `color_looks.validate_look()`；非法即抛 `INVALID_DEPENDENT_ENUM`，**不产生任务、不碰 Blender**。
该错误的 `details` 会平铺到 error 顶层（`parameter` / `value` / `depends_on` / `allowed`），前端据此展示「哪个参数、依赖谁、允许什么」。
`_coerce_enum` 对带 `depends_on` 的参数直接放行原始字符串（不做静态候选校验），交给这一层判定。

### 7.8 恢复基线与 run / preset 三类值

- `restore_baseline()` 与提交草稿共用 `_normalize_values(values, look_map)`，**不盲写旧字符串**；回退时返回带 `warning` 的 note。
- 任务结果 `parameters[<id>]` 记录 `configured_value`（原始草稿）/ `effective_value`（真实 identifier）/ `display_label`。

### 7.9 前端联动

- 状态：`lookMap`（全量能力表）、`lookRequestToken`（代次守卫）。
- 切换 `view_transform` → `onViewTransformChange()`：先 `refreshLookOptions()` 用**本地**能力表刷新候选并按 `normalizeLook()` 迁移旧值，再 `schedulePreview()`；**刷新成功前不提交草稿**。
- 本地缺该视图时先提示「正在向 Blender 确认…」，`loadLookOptions()` 带 token，`token !== lookRequestToken` 时直接丢弃，避免旧响应覆盖新列表。
- `applyValuesToControls()` 先按 `view_transform` 刷候选再落值；候选表里没有目标值时**补一项但保留原样**，绝不伪造 label。

### 7.10 本轮修正的两个隐蔽缺陷

- `build_probe_code` 的 `identifier=None` 一度退化成字符串 `"None"`（合法 look），会把探测结论带偏 —— 已改为传 Python `None`；
- `build_set_code` 一度把值为 `None` 的参数写成字符串 `"None"`，会被 Blender 拒绝 —— 已改为跳过该参数。

## 8. 本地预设与 CI 实现设计（MVP-03 第一批）

### 8.1 为什么不用 `localStorage`

浏览器的 `localStorage` 有几个不可接受的属性：按 origin 隔离、清缓存即丢失、
无法被用户备份或分享、也无法跨机器。预设是**用户的资产**，因此落在文件系统：

```
%LOCALAPPDATA%\CartoonModelShader\presets\
```

用 `TOON_TUNER_PRESET_DIR` 可整体覆盖（测试与自定义部署）；`LOCALAPPDATA` 缺失时兜底到
`~/.local/share/CartoonModelShader/presets/`。**默认路径绝不在仓库内**，测试里有一条
断言专门钉住这一点。

### 8.2 文件布局与身份

- 文件名 = `slugify(name) + ".json"`，方便用户直接浏览/备份/分享预设目录；
- **稳定身份**是文件内的 `preset_id`（12 位 hex），不是文件名。重命名只改 `name` 与文件名，
  身份不变，前端已有的引用不会失效。
- `slugify` 只处理真正危险的部分：Windows 保留字符 `<>:"/\|?*` 与控制字符、结尾的点与空格、
  Windows 设备名（`CON`/`PRN`/`NUL`/`COM1-9`/`LPT1-9`），长度上限 60。
  **中文原样保留** —— UTF-8 文件名在三大平台都合法；净化的只是文件名，预设里的 `name` 不动。
- 两个不同名字净化后可能撞文件名（`a/b` 与 `a:b` → 都是 `a-b`），因此写入时做
  唯一化：同名文件的 `preset_id` 不同就追加 `-2`、`-3`。

### 8.3 校验分层

按「越靠前的层越便宜、越靠前的层越权威」排列：

1. **字段白名单**（顶层与参数条目各一份）—— 多余字段直接拒绝。Pydantic 请求模型也开了
   `extra="forbid"`，未知字段在网络边界就被挡下。
2. **类型与范围** —— 浮点参数复用 `ParamSpec` 的 `minimum`/`maximum`（与提交预览时是
   同一份声明，不存在两套边界）；枚举参数**只做结构性校验**（非空字符串、长度上限）。
   刻意**不**把本机 Blender 的枚举写进预设：预设要能跨版本/跨 OCIO 配置使用，
   真正的合法性在提交预览时对着**当时的**能力表判定。
3. **敏感内容扫描** —— 对规范化后的整份预设做深度遍历，命中即拒绝。模式分三类：
   - 路径类：盘符绝对路径、UNC 路径、`/Users/` 或 `/home/`、`AppData`、`%TEMP%` 等环境变量、
     `toon-tuner-previews`、`\xxx.png` 这类贴图/模型文件路径；
   - 工程类：`.blend` 引用；
   - 凭据类：疑似凭据的**字段名**（`token`/`secret`/`password`/`api_key`/`credential`/`auth`）
     与疑似凭据的**取值**（`ghp_`/`github_pat_`/`sk-`/`token=xxx`）。
4. **schema 版本** —— 只接受 `toon-tuner-preset/1`。缺失或显式 `null` 按当前版本处理；
   其余（含空串、其它版本号、非字符串）一律 `PRESET_SCHEMA_UNSUPPORTED`。
   **不自动迁移、不猜版本** —— 猜错就是静默改变取值。

命中敏感内容时**拒绝保存而不是清洗**：清洗会让用户以为存下了、其实被改过，比直接报错更坏。

### 8.4 原子写入

同目录 `mkstemp` → 写入 → `flush` + `fsync` → `os.replace`。写入中途崩溃也不会留下半个
JSON；`os.replace` 在同一卷上是原子的。重命名时先写新文件、成功后再删旧文件，顺序反了会丢数据。

一个容易踩的点：`Path.glob("*.json")` **会**匹配 `.tmp-xxx.json`（与 shell 的通配语义不同），
所以目录扫描显式排除点开头的文件，否则一次崩溃残留就会在界面上变成一个「坏预设」。

### 8.5 目录扫描：坏的要说出来

`list()` 不会因为某个文件读不动就整体失败，也不会静默跳过。每个读不动/不合法的文件都进
`skipped`，带 `file` / `code` / `message`：

- JSON 解析失败或顶层不是对象 → `PRESET_INVALID`；
- schema 是旧版 → `PRESET_SCHEMA_UNSUPPORTED`（**可见地**拒绝，而不是消失）；
- `preset_id` 与前面某个文件重复 → 记为重复并忽略本文件。

`file` 只给文件名（它派生自用户自己起的预设名），不含任何路径。

### 8.6 加载成草稿：判得了就严格，判不了就明说

`materialize_draft()` 是纯函数（不碰 Blender），只做两件事：取 `active` 参数、按依赖规则规范化
`color.look`。校验强度取决于**能否判定视图变换**：

| 情形 | 行为 |
|---|---|
| 预设自带 `color.view_transform`，或调用方给了基线值，且该视图在能力表里有记录 | **严格**：无等价项就抛 `INVALID_DEPENDENT_ENUM`（含 `allowed`） |
| 拿不到视图 / 能力表为空 / 视图不在能力表里 | **带出原值 + 一条 `note`** 说明延后校验 |

第二行不是「静默放行」：提交预览时服务端仍会对着**当时的**能力表硬校验并报错
（§7.7 的执行前依赖校验）。把「判不了」和「判定了不合法」区分开，才不会出现
`color.view_transform = None 下不合法，允许取值：[]` 这种误导性错误。

取 `effective_value` 优先于 `configured_value`：前者是真正写进过 Blender 的真实 identifier，
后者可能是旧预设里的显示标签。

### 8.7 接口与「不给路径」

七个端点见需求 §22.6。两个设计约束：

- **写入路径由服务端决定**：`PUT` 的 `preset_id` 与 `created_at` 从已存在的文件读出，
  客户端改了也没用（有一条测试专门伪造 `preset_id` 验证这点）。
- **不回本机绝对路径**。列表里的 `storage` 只在目录**等于默认位置**时给出占位符写法
  （`%LOCALAPPDATA%\CartoonModelShader\presets`），其余一律回 `<自定义预设目录>`。
  之所以连「相对部分」都不给：那部分可能嵌套用户名（例如系统临时目录
  `…\Temp\pytest-of-<用户名>\…`），拼出来就是一条路径线索。

预设接口**完全不依赖 Blender** —— 有一条测试把配置指向必然连不上的端口，预设的增删改查照常工作。

### 8.8 CI 设计

`.github/workflows/test.yml`：

| 项 | 取值 | 理由 |
|---|---|---|
| Runner | `windows-latest` | 只承诺 Windows |
| Python | `3.11`、`3.12` | 与 `README` 声明一致，两个版本都验 |
| 依赖 | `pip install -r requirements.txt` | 任务书要求装完即可直接 `pytest` |
| 命令 | `python -m pytest` | 走 `pytest.ini` 的 `testpaths` / `pythonpath` |
| 触发 | PR + `main` push + 手动 | 闸门要拦在合入前 |
| `PYTHONUTF8` | `1` | 源码与断言里全是中文，固定代码页会把断言失败信息打成 `UnicodeEncodeError`，反而掩盖真正的失败原因 |
| 权限 | `contents: read` | 最小权限 |
| 产物 | **无** | 测的是纯 Python 逻辑，不需要留任何文件 |

真实 Blender / 真实浏览器验收**不进 Runner**：需要 Blender 本体、GPU 与本地模型，属于人工步骤。
`browser_check.mjs` 因此也不在 pytest 的收集范围内。

### 8.9 与既有模块的关系

- 复用 `errors.ToonTunerError` 与状态码/`retryable`/`hint` 表，新增 5 个 `PRESET_*` 码；
