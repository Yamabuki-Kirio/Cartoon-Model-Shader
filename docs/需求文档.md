# 本地卡通渲染调参工具需求文档

版本：0.1（需求初稿）  
日期：2026-10-09  
状态：核心范围已确认  
参数数据源：`<MODEL_DIR>\参数面清单.json`（schema `toon-param-surface/1`）

## 1. 产品概述

开发一款仅在本机运行的 Blender 卡通渲染调参工具。用户在 Blender 中打开一个待渲染的 `.blend` 模型后，通过可视化界面调整卡通渲染参数，点击“查看效果”即可得到预览图；满意后可以保存预设、应用到当前工程并导出正式渲染。

工具需要连接一个常驻 Blender 会话，避免每次预览重新启动 Blender、重新追加资源和重建整条管线。实测完整冷运行约 7–8 秒，其中管线搭建约 5.8 秒、正式渲染约 1.3 秒；在已加载场景中只修改参数并重渲约 0.75–2.5 秒。因此，本产品的主要目标是把调参反馈压缩到 1–3 秒，同时保证每次预览可复现、可回滚且不会累积污染。

## 2. 产品目标

1. 用户无需编辑 Python 脚本即可调节辉光、色彩管理、Cel 色阶、描边、环境、渲染质量等参数。
2. 常用参数调整后，预览反馈达到 1–3 秒级。
3. 每次预览都基于同一份基线状态计算，避免连续调整造成节点、灯光、材质或修改器重复叠加。
4. 清楚区分“源工程存盘值”“当前实际生效值”“实测校正值”“脚本默认值”和“Blender 5.x 已移除参数”。
5. 区分 faithful 与 enhanced 两条产品管线，不再把两者混为一种模式。
6. 严格处理未匹配材质，不以静默兜底制造“渲染成功”的假象。
7. 保存完整的参数预设、实际生效参数、渲染结果与运行记录，保证结果可复现。

## 3. 非目标与已知边界

第一版不承担以下工作：

- 不取代 Blender 的建模、骨骼、姿态、动画和物理编辑功能。
- 不承诺自动正确识别 `Material0`、`Material1` 等无语义材质；此类材质需用户手工指定类别。
- 不在第一版完整还原 MMD 球面贴图、toon 贴图等多层材质逻辑；现有管线仍以单张基础色贴图为主，但界面应展示该缺口。
- 不支持远程公网访问；服务默认仅监听 `127.0.0.1`。
- 不把源工程已被旁路的节点参数描述为“当前生效参数”。

## 4. 推荐产品形态

### 4.1 前端

采用本地 Web 界面：HTML/CSS/JavaScript，由 Windows 上的普通浏览器打开。第一版不封装独立桌面程序。

选择本地 Web UI 的理由：

- 色带、颜色选择器、滑块、A/B 对比和图片缩放等组件成熟；
- 与 Blender 进程解耦，界面崩溃不会破坏 Blender 场景；
- 后续可封装为 Tauri/Electron，但 MVP 无需先承担桌面壳复杂度；
- 参数面可由 `参数面清单.json` 动态生成，而非把控件写死；最终数量由静态 schema 与运行时能力探测共同决定。

### 4.2 本地控制服务

本地服务负责：

- 管理浏览器与 Blender 的连接；
- 校验参数 schema、类型、范围和模式适用性；
- 对任务排队、取消和去抖；
- 保存预设、缩略图、运行记录和导出文件；
- 向前端推送状态、进度和最新预览图。

建议使用 WebSocket 处理实时状态与预览通知，HTTP API 处理初始化、预设和文件操作。

### 4.3 Blender 端插件/桥接器

Blender 端保持常驻，负责：

- 读取当前打开的场景和模型；
- 建立或检查卡通渲染管线；
- 采集真实参数与节点能力；
- 从基线恢复状态并应用参数集；
- 执行预览或正式渲染；
- 返回实际生效参数、警告、耗时和图片路径。

直接复用现有 Blender MCP 开放的 `127.0.0.1:9876` 行分隔 JSON 接口，不额外安装通信插件。工具在现有接口之上增加会话协议层，包括协议版本、任务 ID、能力查询、错误码和状态查询；如果接口不能主动推送，则由本地控制服务进行短间隔非阻塞轮询，禁止固定 `sleep`。

## 5. 核心状态模型

### 5.1 状态定义

- 原始工程状态：用户打开 `.blend` 时的状态，不由工具覆盖。
- 工具基线状态：用户点击“初始化管线”后，工具确认过的可渲染状态。
- 草稿参数：界面中正在调整、尚未提交到工程的完整参数集。
- 预览状态：从工具基线恢复相关参数后，一次性应用草稿参数得到的临时状态。
- 已提交状态：用户明确点击“应用到工程”后保存的状态。
- 预设：独立 JSON 文件，包含已配置值、已生效值、适用模式、Blender 版本及来源信息。

### 5.2 预览的推荐实现

不建议每次“查看效果”都关闭 Blender 并从磁盘重新打开工程；这会重复支付约 5–6 秒的启动和建管线成本。

也不建议简单地在上一次预览状态上继续叠加修改，因为灯光、修改器、节点或材质重建存在累积污染风险。

推荐流程：

1. 初始化时创建工具基线快照。
2. 用户调整参数时只更新前端草稿，不立即永久写入工程。
3. 点击“查看效果”后，Blender 端按参数所属层级恢复受影响部分的基线值。
4. 一次性应用当前完整草稿参数集，而不是只发送最后变化的单个参数。
5. 执行预览渲染并返回实际生效值。
6. 下一次预览再次从同一基线恢复后计算。
7. 只有点击“应用到工程”时，才把当前草稿变为新的已提交状态；用户可选择是否同时更新基线。

这种“常驻进程 + 基线恢复 + 完整参数集应用”方案兼顾速度与无污染性。

### 5.3 快照策略

MVP 建议同时采用两层保护：

- 内存参数快照：记录所有受控属性、节点插座值、灯光规格、修改器状态及对象引用，用于快速恢复 L0/L1 参数。
- 临时基线 `.blend`：初始化成功后保存到工具工作目录，用于 L2/L3 操作失败或场景结构异常时完整恢复。

禁止直接覆盖用户原始 `.blend`。正式保存必须使用“另存为”或取得用户明确确认。

## 6. 用户工作流

### 6.1 首次连接

1. 用户启动 Blender，并打开待渲染 `.blend`。
2. 用户在工具中点击“连接 Blender”。
3. 工具显示 Blender 版本、文件路径、活动场景、相机、网格数、材质槽数和连接状态。
4. 工具执行只读预检：检查 mmd_tools、源工程路径、渲染引擎、材质命名、缺失贴图和 Blender 能力。
5. 用户点击“初始化卡通管线”。
6. 工具建立基线快照并生成第一张基线预览。

### 6.2 调参

1. 用户选择 faithful 或 enhanced 工作区。
2. 用户编辑参数；界面显示值来源、重算代价和预计耗时。
3. L0 参数可选择自动预览；其他参数默认点击“查看效果”。
4. 工具从基线应用完整草稿并渲染。
5. 界面展示当前图、基线图、A/B 滑动对比和可选差异热力图。
6. 用户可以撤销、重做、恢复分组默认值或恢复整个基线。

第一版只处理当前活动场景中的一个主要角色。初始化时记录角色的世界变换和包围盒，并要求角色处于管线支持的基准坐标。若用户移动角色，工具应提示灯光装置仍以原世界坐标为基准，要求重新建立基线或恢复角色位置。多角色、灯光随角色局部坐标生成及灯光碰撞隔离留待后续版本。

### 6.3 导出

1. 用户点击“正式渲染”。
2. 工具恢复正式分辨率和采样数。
3. 渲染完成后写出 PNG、参数预设和运行清单。
4. 用户可选择“应用到当前工程并另存为”。

- 最近一次渲染耗时；

按组展示：

- 色彩管理；
- Tonemapping；
- Cel 色阶；
- 描边；
- 世界环境；
- 材质归类；
- 贴图；
- 灯光；

### 7.4 右侧属性面板

提供：

- 恢复基线；

## 8. 参数和重算层级

### L0：合成器与显示参数

目标反馈：约 0.75–1.5 秒。

包括辉光、曝光、Gamma、View Transform、Look、Tonemapping 等。默认启用自动即时预览：参数停止变化 250–400 ms 后提交最新草稿并渲染；旧的待执行预览自动取消或丢弃。用户仍可关闭自动预览并改用“查看效果”按钮。

### L1：共享节点组和对象属性

目标反馈：约 2–3 秒。

包括 Cel 色阶、Emission、描边宽度/颜色、世界强度、预览采样和阴影等。在滑块释放或颜色选择器确认后渲染，不在拖动的每一帧渲染。

### L2：材质重建类参数

目标反馈：约 5 秒。

包括材质归类、基础贴图选择、色彩空间和输出分辨率。必须点击“应用并预览”，显示进度和影响范围；失败时恢复临时基线。

### L3：结构性参数

目标反馈：约 7–8 秒。

包括管线模式切换、重新追加源资源、灯光装置重建、相机策略变化等。使用独立“重建管线”操作，并在执行前提示影响。

## 9. Cel 色阶编辑器

Cel 色阶是 MVP 的重点功能。

需求：

- 按节点组显示 Skin、Hair、Cloth、Dark、Eyes、Face Soft、Eyes Unlit 等色带；
- 每个色带以可拖动色标展示位置和颜色；
- 明确显示 CONSTANT 插值；
- 编辑暗面、中间面、亮面颜色及 Emission Strength；
- 支持组内复位、复制到其他组、保存为色阶预设；
- 修改共享组前显示“将影响多少个材质”；
- 专用 `Sakura_Hair_Reference` 缺乏可解析色阶数据时，显示为只读或提供“一键回退 Cel_Hair”。

## 10. 材质归类工作区

初始化时生成材质表：

| 材质名 | 当前节点组 | 命中规则 | 贴图 | 状态 | 手工指定 |
|---|---|---|---|---|---|

规则：

- 严格匹配默认开启；
- 有未匹配材质时禁止正式渲染；
- 用户可逐材质指定 Skin/Hair/Cloth/Dark/Eyes/Face 等；
- 手工指定优先于正则规则，并可保存为模型专属映射；
- 非严格兜底只能放在“高级/诊断”区域，并显示明显风险提示；
- 展示基础贴图选择及被丢弃的 sphere/toon/normal/mask 贴图，不能让用户误以为这些贴图仍参与渲染。

## 11. 任务与并发模型

- 同一 Blender 会话同一时间只允许一个写入或渲染任务。
- 每个任务具有唯一 `job_id`、类型、创建时间、状态、进度和取消标志。
- 用户快速连续修改参数时，只保留最新待渲染草稿；尚未开始的旧预览任务应取消。
- 正在渲染的任务可选择完成后丢弃结果，或在 Blender 支持安全取消时中止。
- 不使用固定 `sleep`；通过 WebSocket 状态、任务查询或完成事件等待。
- 返回结果必须核对 `job_id`，旧任务结果不得覆盖新参数的预览。

## 12. 建议接口

### HTTP

- `GET /api/status`：服务与 Blender 状态。
- `POST /api/connect`：连接指定 Blender 端口。
- `POST /api/session/initialize`：预检、建立管线和基线。
- `GET /api/session/parameters`：返回参数 schema、基线值、草稿值和实际值。
- `PATCH /api/session/draft`：更新草稿，不立即写入工程。
- `POST /api/render/preview`：从基线应用完整草稿并渲染。
- `POST /api/render/final`：用正式质量渲染。
- `POST /api/session/reset`：恢复基线。
- `POST /api/session/commit`：应用到工程；保存工程需单独确认。
- `GET/POST /api/presets`：读取或保存预设。
- `GET /api/jobs/{id}`：查询任务状态。
- `POST /api/jobs/{id}/cancel`：取消任务。

### WebSocket

事件至少包括：

- `blender.connected` / `blender.disconnected`；
- `session.initialized`；
- `job.started` / `job.progress` / `job.completed` / `job.failed`；
- `preview.ready`；
- `parameters.effective`；
- `materials.unmatched`；
- `scene.external_change_detected`。

## 13. 参数记录格式

工具应区分三类值：

- `configured_value`：用户或预设配置的值；
- `effective_value`：Blender 实际找到并成功应用的值；
- `active`：该参数在当前模式是否参与输出。

例如 faithful 模式下 Glow 可以保留配置，但必须记录：

```json
{
  "id": "glow.threshold",
  "configured_value": 1.5,
  "effective_value": null,
  "active": false,
  "inactive_reason": "faithful 模式没有 Glare 节点"
}
```

这将修复现有 `run_manifest.json` 把“已配置”误当成“已生效”的缺口。

## 14. 错误处理与保护

- Blender 断开：保留草稿，重连后要求重新验证场景指纹。
- 用户在 Blender 中手工修改场景：检测关键数据版本或指纹变化，提示“重新建立基线”或“忽略并继续”。
- 参数应用失败：恢复本次操作前状态，不留下半应用节点。
- 材质未匹配：显示清单并阻止正式渲染。
- 缺失贴图：显示绝对路径、材质和节点，不静默替换。
- 参数在当前 Blender 版本不存在：标记 `unsupported`，不得假装应用成功。
- “应用到工程”提供“覆盖当前文件”和“另存为”两种方式。默认选中“另存为”。选择覆盖时必须显示目标绝对路径、进行二次确认，并在同目录生成带时间戳的可恢复备份后才允许写入。
- 本地控制服务默认仅监听 localhost，并使用本次启动随机令牌验证请求。

## 15. 性能要求

- L0 预览：目标 P50 ≤1.5 秒，P95 ≤3 秒。
- L1 预览：目标 P50 ≤3 秒，P95 ≤5 秒。
- L2 应用与预览：目标 P95 ≤8 秒。
- L3 重建：目标 P95 ≤12 秒。
- 前端操作到任务开始反馈 ≤100 ms。
- 自动预览应有去抖和过期任务丢弃机制。
- 默认预览质量：540×990、EEVEE 4–8 samples。
- 正式质量默认恢复：1080×1980、16 samples。

## 16. MVP 范围

第一版先实现高价值参数，参数界面由 schema 驱动并保留逐步开放能力；最终数量由静态 schema 与运行时能力探测共同决定。MVP 必须包含：

1. 在 Windows 上通过现有 `127.0.0.1:9876` Blender MCP 连接一个本机 Blender 会话；
2. 读取当前已打开 `.blend`；
3. 初始化/检查现有卡通管线；
4. 基线快照、恢复和无污染预览；
5. faithful/enhanced 两个工作区；
6. 辉光、曝光、色彩 Look、世界强度、描边宽度、采样和透明背景控件；
7. 7 组 Cel 色阶编辑器；
8. 严格材质匹配与手工归类；
9. 预览图、A/B 对比、背景切换；
10. 草稿撤销/重做、保存/加载预设；
11. 正式渲染和运行清单；
12. 已配置/已生效/当前是否活动三套参数记录；
13. L0 参数自动即时预览，L1–L3 手动触发；
14. 任务状态查询或推送，不使用固定 sleep；
15. 覆盖当前 `.blend` 与另存为两种保存方式，覆盖前自动备份。

MVP 后再考虑：

- 多层 MMD 贴图重建；
- 多相机、多视角批量预览；
- 动画帧和物理帧选择；
- 多模型批量套用预设；
- 预设缩略图库；
- Tauri/Electron 桌面封装；
- 参数自动搜索与推荐。

## 17. 验收标准

1. 在 Blender 已打开测试模型后，工具能在不重启 Blender 的情况下连续完成 20 次参数预览。
2. 连续预览后，受控灯光、材质节点、描边修改器数量不增加，恢复基线后关键状态与初始化快照一致。
3. 同一参数集重复渲染的差异不超过已测 EEVEE 波动范围：最大通道差 ≤2/255，差异像素比例约 ≤0.0015%。
4. L0/L1 预览达到性能目标。
5. faithful 模式不创建或启用 Glare/Tonemapping；相关参数显示为不活动。
6. enhanced 模式默认采用校正辉光值：Threshold 1.5、Strength 1.0、Size 0.3。
7. Blender 5.x 不存在的 Glare Mix 不可编辑，且工具明确显示原因。
8. 有未匹配材质时，正式渲染被阻止，并允许用户手工指定节点组。
9. 点击恢复基线后，预览图与基线图只允许出现已知的微小 EEVEE 非确定性差异。
10. 输出预设与运行清单能重建同一完整参数集，并记录实际生效参数。
11. 默认不覆盖用户原始 `.blend`；用户明确选择覆盖时，工具先生成可恢复备份并再次确认目标路径。
12. Blender 断连、任务失败或参数越界时，界面提供可理解的错误和恢复方式。

## 18. 已确认的产品决策

1. 仅支持 Windows。
2. 第一版使用普通浏览器打开本地 Web 界面，不要求独立桌面程序。
3. 直接复用 Blender MCP 已开放的 9876 端口，不另装通信插件。
4. 第一版只处理当前场景中的一个主要角色。
5. 当前灯光装置按世界坐标工作；角色移动、多角色灯光隔离和灯光碰撞问题暂不纳入第一版。
6. L0 参数默认自动即时预览；较高代价参数保留“查看效果/应用并预览”操作。
7. 第一版先实现高价值参数，后续扩展到完整参数面（数量由静态 schema 与运行时能力探测共同决定）。
8. 保存时同时提供覆盖当前 `.blend` 与另存为；默认另存为，覆盖前确认并自动备份。

## 19. 不阻塞开发的默认决策

- faithful/enhanced 共享材质、灯光、相机等基础参数，分别维护合成器参数；

## 20. 预览取景（构图）补充需求

> 增补批次：MVP-02 后续修复。起因：预览渲染直接沿用工程当前相机，而该相机带关键帧动画且构图极近，人物在 PNG 内已经出画（实测最坏角点超出画面 7.13 倍），
> 用户会把「出画」误判成调参效果。本节为增量需求，**不修改**第 1–19 节的既有约定。

### 20.1 取景诊断栏

页面顶部必须显示四项只读事实：

- 当前帧（`scene.frame_current`）；
- 当前相机（`scene.camera.name`）；
- 该相机是否带动画（对象级 `action` 与数据级 `data.action` 的关键帧曲线数）；
- 当前角色包围盒是否**完整落在相机画面内**；若出画，给出按画面边长计的越界比例（左/右/下/上）。

### 20.2 基线快照必须包含取景前提

建立基线时必须一并记录：`frame_current`、`frame_start/end`、`scene.camera`、相机世界变换、`lens`、`shift_x`、`shift_y`、
`sensor_width/sensor_height/sensor_fit`、相机动画信息、主要角色分组与逐对象 `matrix_world` + 包围盒、角色并集包围盒、渲染分辨率与当前取景投影结果。

### 20.3 外部改动检测（硬失效）

若在基线建立之后，当前帧或相机被**外部**（Blender 界面或其它脚本）改动，工具必须：

- **停止自动预览**（不再因滑块变化而重渲）；
- 显示「当前帧/相机已变化，请刷新基线」，并列出具体原因（帧变化、相机切换、相机位移、相机旋转、焦距变化、shift 变化）；
- **不得**把新构图当作本次参数调整的效果展示，旧画面保持不动；
- 禁用「重新取景」，直到用户点「建立 / 刷新基线」。

角色自身的漂移（角色位移、角色范围变化、分组变化）与相机动画本身只产生**软告警**，不阻断预览。

### 20.4 预览取景方式

页面提供「预览取景方式」选择：

| 取值 | 含义 |
|---|---|
| `current_camera` | 沿用工程当前相机（**默认**） |
| `auto_full_body` | 自动全身 |
| `auto_upper_body` | 自动半身 |
| `auto_headshot` | 自动头像 |

### 20.5 自动取景的临时相机约束

自动取景必须使用**独立的临时预览相机**：

- **不修改**用户原相机（位置、朝向、焦距、shift、传感器全都不动）；
- **不改变**原相机的动画（不写关键帧、不改 `action`）；
- 不把临时相机保存进用户工程；
- 预览结束后恢复 `scene.camera`；
- **失败时也必须在 `finally` 中恢复并清理**，不得残留临时相机对象或相机数据块。

### 20.6 自动取景的取景算法

- `auto_full_body` 依据**主要角色**的**世界空间**包围盒计算；
- 只使用角色**真实网格**：排除刚体代理、描边壳、`hide_render` 对象、不可见对象、无材质槽对象；
- 保留约 10%–15% 的**安全边距**（可调，见 20.7）；
- 保持输出纵横比，取景诊断与实际渲染共用同一画面形状；
- 正确处理模型**不在世界原点**的情况（按世界坐标求交，不假设原点）；
- 不依赖固定灯光坐标来改变角色位置。

### 20.7 重新取景与安全边距

- 提供「重新取景」按钮：以当前草稿 + 当前取景方式立即重渲一张；
- 提供「安全边距」参数（0–40%，默认 15%）：越大人物越小、留白越多。

### 20.8 界面标识

页面必须明确标识当前画面来源：

- 「**当前相机预览**」——沿用工程相机，画面即用户自己的构图；
- 「**临时自动取景 · 不改动用户相机**」——使用临时相机，并注明渲染后会恢复原相机。

### 20.9 验收

1. 当前相机模式下，相机世界变换/焦距/shift 与当前帧均不被改动；
2. 自动取景后角色包围盒完整进入画面（含离世界原点、含刚体与描边壳的场景）；
3. 预览结束恢复原 `scene.camera`；渲染抛错时同样恢复，且无临时相机残留；
4. 用户切帧后能检测到基线失效（横幅 + 停止自动预览 + 禁用重新取景 + 画面不被顶替）；
5. 相机有关键帧时正确显示动画告警，且自动取景不写入任何关键帧。

## 21. 依赖枚举（视图变换 → Look）补充需求

> 增补批次：MVP-02 后续修复。起因：切换「视图变换」后，完整草稿仍按旧值提交
> `look = "AgX - High Contrast"`，而该视图下 Blender 只接受
> `('None', 'Very High Contrast', 'High Contrast', …)`，于是预览报
> `BLENDER_SCRIPT_ERROR`。本节为增量需求，**不修改**第 1–20 节的既有约定。

### 21.1 问题定性

`scene.view_settings.look` **不是独立参数**，而是**依赖 `view_transform` 的枚举**：
同一个字符串在 AgX 下合法，切到 Standard 就可能直接抛错。两个「看起来能用」的候选来源都不能采信：

1. `bl_rna.properties['look'].enum_items` —— 无 UI 上下文时只返回 `NONE`（Blender 5.2.1 实测 `items_count == 1`），完全不可用；
2. `PyOpenColorIO.getLookNames()` —— 那是 OCIO 配置的**全局** look 名单，**不是**当前 `view_transform` 下 Blender 接受的枚举。

旧实现直接拿第 2 项当候选，于是把 AgX 专属档位写进了只接受通用档位的视图。

### 21.2 选项必须区分 value 与 label

下拉框的每一项是 `{"value": …, "label": …}`：

- `value`：**Blender 真实 identifier**，也是唯一允许写进 Blender 的东西；
- `label`：界面显示文本，可由前端组合（族前缀视图下形如 `"AgX - High Contrast"`）。

**写进 Blender 的只能是 `value`，永远不能是 `label`。**

### 21.3 只读能力探针

必须提供一个只读探针，输入 `view_transform`，输出该视图下真正合法的 look 枚举：

- 临时记录当前 `view_transform` / `look`；
- 切到目标 `view_transform`；
- 从 Blender RNA 或**可用上下文**读取真正合法的 identifiers；
- `finally` 恢复原 `view_transform` / `look`；
- RNA 在后台上下文不可用时改用赋值探测，但**必须完整恢复**状态；
- **不得**只以 OCIO `getLookNames()` 作为合法性依据。

### 21.4 建立基线时一次扫出全量能力表

建立基线时一次性探测**每个** `view_transform` 对应的合法 Look，返回形如：

```json
{
  "AgX":      [{"value": "None", "label": "None"},
               {"value": "AgX - High Contrast", "label": "AgX - High Contrast"}],
  "Standard": [{"value": "None", "label": "None"},
               {"value": "High Contrast", "label": "High Contrast"}]
}
```

若某版本只提供通用 contrast identifiers，`label` 可由前端组合（如 `"High Contrast"` → `"AgX - High Contrast"`），
但 `value` 必须保持 Blender 实际 identifier。此后前端切换视图变换通常是**零 Blender 调用**。

### 21.5 前端联动

- 切换 `view_transform` 后**立即**刷新 Look 下拉框；
- 移除当前视图下无效的 Look；
- 旧 Look 存在等价项时**按规范化名称迁移**（`"AgX - High Contrast"` → `"High Contrast"`）；
- 没有等价项时回退 `"None"`；
- **不立即把无效旧值发送给 Blender**。

### 21.6 应用顺序固定

完整草稿的应用顺序固定为：

a. `view_transform` → b. 重新取得/验证 `allowed_looks` → c. `look` → d. `exposure` → e. `gamma` → f. 其他参数。

### 21.7 执行前依赖校验与稳定错误码

后端必须在**执行 Blender 脚本之前**完成依赖校验。无效组合返回稳定错误（不得落成通用 `BLENDER_SCRIPT_ERROR`）：

```json
{
  "code": "INVALID_DEPENDENT_ENUM",
  "parameter": "color.look",
  "value": "AgX - Punchy",
  "depends_on": {"color.view_transform": "Standard"},
  "allowed": ["None", "Very High Contrast", "High Contrast", "..."]
}
```

### 21.8 原子化应用

- 先验证全部参数；**全部合法后**再写入；
- 任一写入失败时恢复本次应用前的 `view_transform` / `look` / `exposure` / `gamma`；
- 不能留下「`view_transform` 已变、`look` 未变」的半应用状态。

### 21.9 基线恢复走同一套映射

恢复基线必须使用与提交草稿相同的顺序与映射逻辑，**不能直接盲写旧字符串**。

### 21.10 run / preset 记录三类值

运行记录与预设分开保存三个字段：

- `configured_value`：用户/预设里配置的值；
- `effective_value`：实际写入 Blender 的 identifier；
- `display_label`：界面显示标签。

旧预设里的 `"AgX - High Contrast"` 在加载时迁移为 `value="High Contrast"` / `label="AgX - High Contrast"`（视 Blender 版本而定）。

### 21.11 验收

1. AgX + `"High Contrast"` 能成功（规范化为该版本的真实 identifier）；
2. label `"AgX - High Contrast"` 不会**直接**写入 Blender；
3. 切换 AgX → Standard 后 Look 列表刷新；
4. 旧 Look 不合法时回退 `None`；
5. 视图切换后完整草稿可以预览，且不再出现 `BLENDER_SCRIPT_ERROR`；
6. 写 Look 失败时 `view_transform` 被恢复；
7. 恢复基线后 `view_transform` / `look` 与基线逐项一致；
8. 旧版预设名称能正确迁移；
9. 前端 `option.value` 与显示文本各自由 value / label 驱动；
10. 快速连续切换视图时，旧候选请求不会覆盖新列表。

## 22. MVP-03 补充需求：CI 闸门与本地预设

> 增补批次：MVP-03 第一批（**只含 Windows CI 与预设存储后端**）。A/B 对比、预览质量档位的
> 实际应用、会话恢复属于后续批次，见 §22.8。

### 22.1 Windows CI 自动闸门

在开发新功能**之前**先建立自动闸门：

- 运行环境：`windows-latest`（本工具只承诺 Windows，用别的平台跑等于承诺了不支持的平台）；
- Python 版本矩阵：**3.11、3.12**；
- 安装 `requirements.txt`；
- 执行 `pytest`；
- **不依赖真实 Blender**（测试自带假 MCP 与假 `bpy` 桩）；
- **不上传**模型、预览图或日志；
- 在 PR 与 `main` 的 push 上触发。

真实 Blender / 真实浏览器验收**仍是人工步骤**，不能放进普通 GitHub Runner。

### 22.2 预设的存储位置

预设保存在**用户目录**，不进仓库：

```
%LOCALAPPDATA%\CartoonModelShader\presets\
```

- 不得放进仓库；
- 不得把浏览器 `localStorage` 当作**唯一**存储。

### 22.3 预设内容

```json
{
  "schema": "toon-tuner-preset/1",
  "preset_id": "15f92ca1b396",
  "name": "柔和辉光",
  "created_at": "2026-10-09T10:58:47+08:00",
  "updated_at": "2026-10-09T10:58:47+08:00",
  "pipeline_mode": "enhanced",
  "framing_mode": "auto_full_body",
  "framing_margin": 0.15,
  "preview_quality": "standard",
  "parameters": {
    "color.exposure": {
      "configured_value": 0.2,
      "effective_value": 0.2,
      "active": true
    }
  }
}
```

- `preset_id`：**稳定身份**，重命名不变；
- `parameters`：`参数 id -> {configured_value, effective_value, active}`。
  `configured_value` 是配置值（旧预设里可能是显示标签），`effective_value` 是真正写进
  Blender 的真实 identifier，`active=false` 表示只作记录、不参与应用（见 §13）。
- `framing_margin` 是对需求原文的一处**补充**：需求只列了 `framing_mode`，但安全边距
  同属取景运行设置，不存就无法复现同一构图。默认为 `0.15`（与当前一致）。

**禁止保存**：

- `.blend` 绝对路径；
- 用户目录；
- 模型名称或贴图路径；
- MCP Token（以及任何形式的凭据、密钥）；
- 临时预览路径。

命中即**拒绝保存**，不做静默清洗 —— 清洗会让用户以为存下了、其实被改过。

### 22.4 schema 版本处理

只接受 `toon-tuner-preset/1`。旧版或未知版本一律**显式报错** `PRESET_SCHEMA_UNSUPPORTED`，
不静默迁移、不静默丢弃、不「猜一个版本」。

### 22.5 稳定错误码

| 代码 | HTTP | 含义 |
|---|---:|---|
| `PRESET_NOT_FOUND` | 404 | 预设不存在 |
| `PRESET_INVALID` | 400 | 内容不合法（未知参数、越界取值、含禁止保存的内容） |
| `PRESET_SCHEMA_UNSUPPORTED` | 400 | schema 版本不支持 |
| `PRESET_NAME_CONFLICT` | 409 | 同名预设（名称不区分大小写） |
| `PRESET_STORAGE_ERROR` | 500 | 预设目录读写失败 |

### 22.6 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/presets` | 列表 + 运行设置白名单（`quality_tiers` / `pipeline_modes` / `framing_modes` / `defaults`） |
| `GET` | `/api/presets/{id}` | 读取单个预设 |
| `POST` | `/api/presets` | 新建 |
| `PUT` | `/api/presets/{id}` | 覆盖保存（身份与创建时间由服务端保留） |
| `POST` | `/api/presets/{id}/rename` | 重命名（身份不变） |
| `POST` | `/api/presets/{id}/duplicate` | 复制为新预设（**新身份**） |
| `DELETE` | `/api/presets/{id}` | 删除 |

响应里只给**可展示**的存储位置写法（如 `%LOCALAPPDATA%\CartoonModelShader\presets`），
**不得**出现本机绝对路径。

### 22.7 预设不能静默应用

- 未知参数 id、越界取值、非白名单字段 → 报错；
- 非法/旧 schema → 报错；
- 依赖枚举（`color.look`）无法确认合法性时，**带出原值并明确说明「延后到提交预览时校验」**，
  而不是假装校验通过。

### 22.8 本批次边界

本批次**只做** Windows CI 与预设存储后端。以下属于后续批次：

- A/B 对比（并排 / 拖动分割 / 快速切换 / 棋盘格等背景 / 参数差异摘要）；
- 预览质量档位的**实际应用**（临时改 Blender 分辨率与采样、`finally` 恢复并回读验证）；
- 会话恢复（浏览器刷新后恢复草稿、已选预设、取景模式、预览质量、A/B 引用与未提交状态）。

`preview_quality` 的值本批次已能保存与校验，白名单与名义分辨率/采样见
`PREVIEW_QUALITY_TIERS`（快速 360×660/4、标准 540×990/8、高质量 1080×1980/16）。
实际渲染时按**工程纵横比**等比缩放到档位长边，不强行套用名义宽高 —— 预览与取景诊断
必须共用同一画面形状（见 §20）。

### 22.9 验收

1. Windows CI 通过；
2. 预设保存、加载、重命名、复制、删除正常；
3. 旧 schema 或非法参数不会被静默应用；
4. 预设加载能复现相同参数；
5. 预设里没有本机敏感路径；
6. 不修改用户的 `.blend`。
