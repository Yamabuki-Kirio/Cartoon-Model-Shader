# 材质图参数面（PR #7）

> 状态：**代码与自动测试完成，真实 Blender 验收尚未执行。**
> 本文档里的「真机验收矩阵」是**待执行清单**，不是已通过的结果。
> 任何 `README` / PR 描述都不应声称材质图已在真实 Blender 上验收。

## 0. 这份文档说什么

材质图参数面把「材质节点树」变成可安全编辑的参数面：探测 → 反向追踪 → 递归 schema →
界面 → 校验 → 写入 → 回读 → 渲染 → 恢复。它覆盖四件事：

1. **支持节点清单**（§2）：哪些 Blender 节点、哪些插座会被识别成参数；
2. **识别等级说明**（§3）：每个参数的置信等级意味着什么、能不能写；
3. **安全模型**（§6）：客户端**无法**绕过的那几条；
4. **已知限制**（§7）与**真机验收矩阵**（§9）。

## 1. 数据流与入口

```text
Blender ──只读探针──▶ surface_probe.describe_groups
                         │
                         ├─▶ material_graph.probe.build_material_graph
                         │      └─▶ material_graph.trace.trace_from_output（反向追踪，最大深度 8）
                         │             └─▶ material_graph.schema.build_parameter_schema
                         │                    └─▶ 递归 schema + 扁平 spec 参数表
                         │
GET /api/material-graph/schema ────────▶ Web 工作台（七个分区 / 可折叠 / 虚拟列表）
POST /api/v4/preview（material_draft）──▶ 服务端校验 → 快照 → 应用 → 回读 → 渲染 → 恢复 → 回读
```

**基线**由 `POST /api/session/baseline` 一并采集（与 v4 参数面同一次探测）。
没有基线时 `GET /api/material-graph/schema` 返回 `NO_BASELINE` —— 那不是失败，
界面提示「先刷新基线」而不是弹红色错误。

材质图草稿与 v4 参数面草稿**共用一份前端草稿与同一个撤销栈**，但在提交时按 id
拆成两个字段：`draft`（v4 参数面）与 `material_draft`（材质图）。服务端把两者编进
**同一个任务**，因此只渲染一次、一起回滚。

## 2. 支持节点清单

判定依据是 Blender 的 `node.type`**常量**（不是名字）。候选插座名只用于「命中判定」，
命中之后还要结构验证（插座必须真的存在且未被上游连线）。

### 2.1 标量 / 颜色 / 色带 / 运算（`confirmed`，默认写入）

| `node.type` | 语义 | 界面分区 | 可编辑插座 → 字段 |
|---|---|---|---|
| `VALUE` | 数值 | 数值参数 | `Value` → `default_value` |
| `RGB` | 颜色 | 颜色与色带 | `Color` → `default_value` |
| `VALTORGB`（挂 `color_ramp`） | 色带 | 颜色与色带 | 色标表 → `elements`（整体替换） |
| `MATH` | 数值运算 | 数值参数 | `Value` / `Value_001` / `Value_002` → `default_value` / `value_1` / `value_2` |
| `MAP_RANGE` | 范围映射 | 数值参数 | `Value` / `From Min` / `From Max` / `To Min` / `To Max` |

`VALTORGB` 的判定走**结构**（节点上真的挂着 `color_ramp`），类型常量只作参考。

### 2.2 着色器常量（`confirmed`，默认写入）

| `node.type` | 语义 | 界面分区 | 可编辑插座 → 字段 |
|---|---|---|---|
| `BSDF_PRINCIPLED` / `BSDF_DIFFUSE` / `BSDF_TOON` / `EMISSION` / `BSDF_EMISSION` / `OUTPUT_MATERIAL` | 着色器 | 常用参数 | `Base Color`（颜色）、`Metallic`、`Roughness`、`Emission Color`（颜色）、`Emission Strength`、`Specular IOR Level` |

与逐材质适配器（`src/server/surface/material.py` 的 6 项白名单）**同一套候选 + 同一条结构验证**，
但定位方式不同：材质图写的是「材质节点树内任意节点的输入插座」，逐材质适配器只定位
「材质输出所连着色器上的候选插座」。

### 2.3 只读的语义（展示与试调，**默认不写**）

| `node.type` | 语义 | 等级 | 只读原因 |
|---|---|---|---|
| `MIX_RGB` / `MIX` | 颜色混合 | `inferred` | `inferred_not_confirmed` |
| `HUE_SAT` | 色相/饱和度 | `inferred` | `inferred_not_confirmed` |
| `BRIGHTCONTRAST` | 亮度/对比度 | `inferred` | `inferred_not_confirmed` |
| `GAMMA` | 伽马 | `inferred` | `inferred_not_confirmed` |
| `INVERT` | 反相 | `inferred` | `inferred_not_confirmed` |
| `REROUTE` | 转接 | `inferred` | `reroute_transparent`（透传，本身没有可写参数） |
| `MIX_SHADER` / `ADD_SHADER` | 着色器混合 | `experimental` | `experimental_semantics` |

理由不是「懒得做」，而是这几类节点的语义**随混合模式或规则变化**：同样一个 `Mix.Fac`，
在 `MIX`（颜色）与 `MIX_SHADER`（着色器）里改变的是完全不同的东西。没有微扰验证就写下去，
等于用一次成功的写入换一个无法预期的画面。

### 2.4 纹理与节点组

| `node.type` | 语义 | 界面分区 | 说明 |
|---|---|---|---|
| `TEX_IMAGE` / `TEX_COORD` / `MAPPING` | 纹理控制 | 纹理控制 | **没有候选可编辑插座**：本工具只调参数，不替换贴图文件。探到即列出，一律只读 |
| `GROUP` | 节点组 | 节点组参数 | 组实例本身只读；组**内部**节点通过穿透进入参数面 |
| 其它未识别类型 | 其它 | 高级影响路径 | `unsupported`，只读，并带 `unconfirmed_capability` |

### 2.5 一律只读的通用规则

| 情形 | 只读原因 |
|---|---|
| 输入插座**已被上游连线** | `linked_upstream`（写 `default_value` 不会生效） |
| 到材质输出的影响路径**不唯一** | `ambiguous_path` |
| 影响链路里**存在环** | `cycle_detected` |
| 超出**最大追踪深度 8** | `too_deep` |
| 入口不唯一 / 没有连接到 `Material Output.Surface` | 整份参数面降级只读（`degraded_reason`） |
| 材质未启用节点 / 探不到节点树 | `available: false`，不伪造任何参数 |

**孤立节点不进参数面**：只有从 `Material Output.Surface` 反向可达的节点才会生成参数。

## 3. 识别等级说明

| 等级 | 含义 | 默认可写 | 界面表现 |
|---|---|---|---|
| `confirmed` | 类型、目标插座与影响路径全部明确 | ✅ | 「已确认」绿色芯片 |
| `inferred` | 影响路径明确，但语义依赖名称或规则推断 | ❌ | 「推测」黄色芯片，且**固定归入「推测参数」分区** |
| `user_confirmed` | 由用户显式确认过 | ✅ | 「用户确认」绿色芯片 |
| `experimental` | 需要微扰验证后才可写 | ❌ | 「实验性」黄色芯片 |
| `unsupported` | 无法安全执行或回滚 | ❌ | 「不支持」红色芯片 |

三条硬约束：

1. **探测流程从不自行产生 `user_confirmed`。** 它只能由上层在用户显式确认后记录。
2. **界面只降级、不升级。** 未知等级 → 按 `unsupported` 处理并强制只读；未知 `kind` →
   `unknown` 只读节点；未知分区 → 归入「高级影响路径」。前端版本比后端旧时，
   新参数宁可只读，也不会看起来可写。
3. **推测参数永远进「推测参数」分区**，不随语义散落到「颜色与色带」里 ——
   混在一起时用户扫一眼分不出哪个结论可信。

每个参数都带 `confidence` / `semantic` / `evidence` / `readonly_reason`，
界面把这些原样展示（含识别依据与完整影响路径），不重新分类、不按名字猜。

## 4. schema 形状

```jsonc
{
  "id": "mg-3f1c…",              // opaque，24 位十六进制哈希；不含节点名
  "label": "Principled BSDF · Roughness",
  "kind": "float",               // float / int / bool / color / vector / enum / ramp
  "confidence": "confirmed",
  "semantic": "shader",
  "semantic_label": "着色器",
  "category": "common",          // common / color / numeric / ramp / node_group / texture / inferred / advanced
  "editable": true,
  "supported": true,
  "readonly_reason": null,
  "evidence": ["节点类型 BSDF_PRINCIPLED 语义确定"],
  "influence_paths": [["Principled BSDF", "Material Output"]],
  "affected_materials": ["model_mesh"],   // 非共享参数：使用该材质的**对象**名
  "shared": false,
  "in_group": null,
  "source_node": "Principled BSDF",
  "source_label": "Principled BSDF",
  "used_outputs": ["BSDF"],
  "value": { "current": 0.5, "baseline": 0.5, "effective": 0.5 },
  "minimum": null,
  "maximum": null,
  "step": null,
  "binding": { "object_type": "MATERIAL_GRAPH_SOCKET", "field": "default_value" }
}
```

色带多三项：`elements`（`{index, position:{value,baseline,minimum,maximum,step}, color:{value,baseline}}`）、
`interpolation`（**复合形状** `{value, baseline, options}`）、`element_count`（**复合形状**，
`editable: false`）。这两个复合形状直接取自 `surface.schema`，**少读一层会让插值静默退化成
`LINEAR`** —— 前端解析层为此专门有回归用例。

`binding` 只暴露 `object_type` 与 `field`，**不含 `object_id`**（那里面才是真实节点名）。

## 5. 执行与回滚

服务端顺序（与 v4 参数面同一套执行器，`src/server/session.py`）：

```text
校验会话令牌 → 校验基线 → 校验结构哈希 → 用当前 schema 解析 opaque 参数 ID
→ 校验值类型与范围 → 计算依赖顺序 → 快照受影响目标 → 应用完整草稿
→ 回读逐项校验 → 渲染 → 恢复快照 → 回读确认恢复
```

三段写入**分开报告**：L0 / Cel（v4 参数面）/ 材质图。任一段失败都触发整体回滚，
失败响应里 `restore` 会分别给出 `l0` / `cel` / `material_graph` 的回读结论与 `code`。
恢复没能确认时给 `ROLLBACK_FAILED` 并明说「Blender 里的取值可能仍不是提交前的状态」——
不会含糊地说一句「已回滚」。

## 6. 安全模型（不可绕过）

| 面 | 处置 |
|---|---|
| **参数 ID** | 客户端只提交服务端生成的 opaque `mg-<hash24>`。任何代码 / 属性路径 / 命令 / 文件路径形态都只是「不在 schema 内的未知参数」（`PARAM_INVALID`），不据此透露任何真实节点名 |
| **节点路径** | 节点名 / 插座名**全部**由服务端探测结果拼出（`object_id = 材质名/节点名/插座名`）。请求体里没有它们的字段位置 |
| **字段白名单** | 只允许 `MATERIAL_GRAPH_SOCKET.default_value` 与 `MATERIAL_GRAPH_RAMP.{elements,interpolation}`。`element_count` 在 `READONLY_FIELDS` 里，**结构性增删色标不可能** |
| **值** | 一律经 `repr()` 量化，绝不字符串拼接；只接受有限数值 / 4 分量颜色 / 色标表；非法即 `PARAM_INVALID` |
| **共享节点组** | 参数属于被多个材质引用的节点组时，`confirmed_shared_groups` 未列出该组即拒绝（`SHARED_PARAMETER_CONFIRM_REQUIRED`），并在 `details` 里列出**会一起改到的材质** |
| **结构指纹** | 材质图结构哈希只含结构（节点增删 / 连线 / 插座结构 / 节点组接口），**不含任何数值**。与基线不符即 `STRUCTURE_CHANGED`，草稿与保存令牌一起作废 |
| **写入顺序** | 写入前用只读探针**实测**一次结构，不只信客户端手里的指纹；已连线插座在 Blender 侧再拒一次 |
| **请求体** | 接口模型 `extra="forbid"`：`script` / `script_path` / `python` / `command` / `scheme` / `executor` 一律 422 —— 请求体里根本没有这些字段的位置 |
| **回滚** | 执行器写前快照、失败即回滚、回读确认；回滚失败明确上报 `ROLLBACK_FAILED` |

材质图**不走**「浏览器提交脚本路径」那条老路：服务端只有固定执行器，
没有任何接口接受脚本路径、方案 ID 或命令（渲染方案的注册表是后续 PR 的事）。

## 7. 已知限制

1. **可写参数不下发值域。** `_bounds` 只给 `mix` 与 `hue_saturation` 两个语义声明值域，
   而这两个语义在 `classify` 里恒为 `inferred` ⇒ 一律降级成只读占位。
   因此**当前没有任何可写材质图参数带 `minimum` / `maximum`**：
   - 界面不会出现滑块（只给精确数值输入）——这是如实反映服务端没给值域，不是缺陷隐藏；
   - 越界闸门本身由执行器单测用**显式声明值域的参数**钉住
     （`tests/test_material_graph_execution.py::test_out_of_range_rejected`），
     另有 `test_writable_material_graph_params_declare_no_range` 把「现状」也钉住：
     后端一旦开始下发值域，那条用例会红，提醒把接口层断言与前端滑块补上。
2. **插值方式只读展示。** schema 不下发可选插值清单（`_ramp_node` 不填
   `interpolation_options`），因此界面不提供下拉框 —— 前端不会编一份 Blender 枚举出来，
   写一个 Blender 不认的字符串，失败会发生在写入那一刻。
3. **嵌套节点组内的节点不会被判为共享。** `shared_groups` 的键是**直接组名**，
   而追踪出来的 `in_group` 是**全链**（`A::B`）。因此嵌套组里的节点 `shared = false`，
   不会触发共享确认。单层组（当前真机的实际形态）不受影响。
4. **预设不覆盖材质图草稿。** `PresetSaveBody` 只有 `parameters` 与 `surface`：
   预设是「v4 参数面 + L0 运行设置」，材质图草稿只通过「应用到工程」（`material_draft`）落盘。
5. **色带的生效值会多一条记录。** 材质图色带写入由两条操作组成（色标表 + 插值），
   因此 `applied_material_graph` 里除了色带自己的 id，还有一条 `<id>.interpolation`。
   它不是参数 id，界面的「生效值」列不会去读它。
6. **`affected_materials` 的语义随参数变化**：共享节点组参数给的是**会一起改到的材质名**，
   其余参数给的是使用该材质的**对象名**。界面按 `shared` 切换标签，不自行解释。
7. **本工具不改动贴图文件。** 纹理节点只列出、只读。
